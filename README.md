# 密码保险箱

一款本地加密的账号密码管理工具：Python 3 + PySide6 桌面程序，数据只保存在本机，
不联网、不上传、不依赖任何云服务。界面为极简扁平风格，自带浅色与深色两套完整主题。

```
┌────────────┬──────────────┬─────────────────────────────┐
│ 导航 / 分类 │  记录列表     │  详情（字段 / 动态口令 / 备注）│
└────────────┴──────────────┴─────────────────────────────┘
```

## 快速开始

**方式一：直接用打包好的 exe（不需要装 Python）**

进入 `dist/密码保险箱/`，双击 **`密码保险箱.exe`** 即可。
整个文件夹一起拷贝分发，不能只拿 exe——运行库在 `_internal` 目录里。

**方式二：从源码运行**

```bash
pip install -r requirements.txt

python main.py            # 从命令行启动（可见日志）
启动密码保险箱.vbs         # 双击启动（无控制台窗口，日常使用推荐）
调试运行.bat              # 出问题时用这个，能看到完整报错
```

首次启动会引导你**给保险箱命名**并设置主密码；之后每次启动都需要输入主密码解锁。
保险箱名称会显示在窗口标题与侧栏，方便区分多个保险箱；创建时若填了名称，
默认文件名也会跟着变成「名称.psvault」。

## 功能

**账号管理**

- 记录标题、用户名、密码、**预留电话、预留邮箱**、网址、分类、标签、备注、两步验证密钥，支持收藏
- 三栏界面：左侧导航（全部 / 收藏 / 安全审计 / 回收站 / 分类 / 标签），中间记录列表，右侧详情
- 实时搜索，可按分类、标签、收藏、安全问题多维度筛选；搜索范围覆盖标题、账号、电话、邮箱、备注与标签
- 一键复制用户名 / 密码 / 电话 / 邮箱 / 网址 / 动态口令，密码默认掩码显示，可临时查看
- 回收站：删除先入回收站，可恢复或彻底删除，支持清空
- 密码历史：改密码时旧密码自动留存，可回溯与复制

**分类管理**

- 默认自带「未分类 / 密钥 / 邮箱 / 社交 / 金融 / 开发 / 购物」，其中「密钥」适合存放各类密钥、恢复码
- 侧栏分类标题旁的齿轮按钮打开**分类管理**：集中新建、重命名、删除
- 侧栏分类项右键也可重命名 / 删除；删除分类不会删记录，其中的记录自动归入「未分类」
- 老版本数据文件打开时会自动补齐新增的默认分类，且只补一次——手动删掉后不会再被加回来

**密码工具**

- 密码生成器：随机密码 / 易记短语 / 数字 PIN 三种模式，可排除易混淆字符、保证每类字符至少出现
- 强度评估：按字符集估算熵，并对键盘序列、重复片段、常见弱口令扣分
- 两步验证：内置 TOTP（RFC 6238）实现，详情页实时显示动态口令与刷新倒计时

**安全审计**

侧栏的「安全审计」是一个**独立视图**：右侧不再是记录详情，而是完整体检报告。

- 每处问题都写明**是哪条记录、属于哪一类、具体原因是什么**，例如：
  - `弱密码（强度较弱）` —— 长度不足 8 位；包含键盘连续序列
  - `与 2 条记录使用了相同密码` —— 重复的账号：某论坛、某邮箱。一旦其中一处泄漏，其余账号会一并失守
  - `已 210 天未修改密码` —— 超过设定的 180 天
- 按「弱密码 / 可被猜到的密码 / 重复使用 / 长期未更换 / 未设置密码 / 明文传输的网址 / 可以更好」
  分组，每组给出处理建议
- 「**可被猜到的密码**」指密码里直接含账号名或网站名（比如 github 的密码是 `Github@2024#`）——
  单看强度可能达标，但知道这些信息的人很容易试出来
- 「**明文传输的网址**」指 `http://` 的公网地址；内网与本机地址
  （`192.168.` / `10.` / `172.16-31.` / `localhost` / `.local`）不计入，避免误报路由器这类设备
- 「**长期未更换**」按**上次更换密码**的时间计算——改备注、加标签不会把密码年龄清零
- 列表里每条记录带风险标签，一眼看出问题类型；点「查看」跳到详情
- **详情页顶部也有风险横幅**（任何视图下都显示），列出这条记录的全部问题，并提供「换个强密码」一键修复
- **不想处理的提示可以忽略**：每个问题行尾有 ⊘ 按钮，忽略后该项不再计入评分；
  详情页的「忽略」可以一次性忽略这条记录的全部风险；被忽略的项集中列在报告底部，
  可单条恢复或「全部恢复」，忽略状态随保险箱一起加密保存

**数据**

- 导入：Chrome / Edge / Bitwarden / LastPass 等导出的 CSV（自动识别中英文表头）、本程序导出的 JSON
- 导出：加密备份（`.psvault`）与明文 CSV（导出前会二次确认）
- 自动多版本备份，见下方「数据不会丢」

**查找与操作**

- 实时搜索 + 分类 / 标签 / 收藏多维筛选
- **排序可切换**：名称（收藏优先）/ 最近修改 / 最近创建，选择会被记住
  （列表标题行右侧的排序按钮）
- **全键盘操作**：搜索框按 `↓` 进列表，`↑`/`↓` 切换记录，`Enter` 编辑，
  `Ctrl+C` 复制密码，`Delete` 删除，`Esc` 回到搜索框

**使用体验**

- 浅色 / 深色两套主题，即时切换，设置随保险箱一起加密保存
- 保险箱名称可在「设置 → 保险箱」中随时修改
- 空闲自动锁定（默认 5 分钟）、最小化时锁定、复制密码后自动清空剪贴板（默认 30 秒）
- 全部图标为程序内置矢量图标，无需任何外部资源文件

## 安全设计

| 环节 | 方案 |
| --- | --- |
| 密钥派生 | scrypt（N=32768, r=8, p=1，随机 16 字节盐），主密码不落盘 |
| 数据加密 | AES-256-GCM 认证加密，任何一位密文被改动都会解密失败 |
| 头部保护 | 文件头（KDF 参数、版本号）作为附加认证数据参与校验，无法被悄悄篡改 |
| 主密码校验 | 不保存密码或校验值，能成功解密即代表密码正确 |
| 更换主密码 | 重新生成盐并用新密钥整体重新加密，随后立刻生成一份新密码的备份 |
| 剪贴板 | 复制的敏感内容按设定秒数自动清空（内容被替换过则不动） |
| 剪贴板历史 | 密码、动态口令会声明 `CanIncludeInClipboardHistory=0` 与 `CanUploadToCloudClipboard=0`，**不进 Win+V 历史、不同步到云剪贴板** |
| 网络 | 程序不发起任何网络请求，没有遥测与同步 |
| 写入校验 | 每次保存后回读校验，解不开就自动回滚到上一版，绝不留下打不开的文件 |
| 独占编辑 | 一份保险箱同时只允许一个实例打开（`QLockFile`）。两个窗口各自写回会让后写的静默覆盖先写的，原子替换挡不住这种丢数据 |
| 写入竞态 | 临时文件/回滚点用唯一文件名并在同目录创建，避免两个实例往同一个文件里写 |

**请务必牢记主密码**：程序没有保存它的任何副本，忘记后数据无法恢复。
数据本身有多版本自动备份兜底，但备份同样需要主密码才能打开。

## 数据不会丢：自动备份与恢复

保险箱文件被强加密保护（改一个字节就打不开），但这也意味着**一次误删或一次损坏
就可能全丢**。为此程序内置了多版本备份机制：

- **每次保存前自动留一份历史版本**；内容没变化时不会重复备份，也不会刷屏
- **两个位置各存一份**：
  - 程序目录：`data/backups/<名称>-20260917-211853.psvault`
  - 用户文档目录：`文档/密码保险箱备份/`
  整个程序文件夹被误删时，文档里的那份仍然在
- 每个位置默认保留最近 **10 份**，超出自动清理最旧的（份数可在设置里改）
- 备份是密文的原样副本，放到网盘或 U 盘都安全
- **改主密码时会自动换一批备份**：先立刻生成一份新密码的备份，确认写好了，
  再清理掉那些"只有旧密码才打得开"的旧备份（可在设置里关掉这个清理）

**三个恢复入口**：

1. **解锁窗口底部**常驻一行「备份 12 份 · 最近 2026-09-17 21:18:53」和「从备份恢复…」
2. **设置 → 数据 → 备份与恢复**：备份列表（位置 / 时间 / 大小）、立即备份、恢复选中版本
3. 如果**主密码报错或文件被改动**，解锁窗口会直接提示「文件可能已被改动，可点下方从备份恢复」

另外，程序每次写入后都会**回读校验**：万一新文件解不开（磁盘故障、被截断等），
会自动用最近的备份回滚到上一个可用版本，并明确告知用户发生了什么。

**一份保险箱只能开一个窗口**：启动第二个实例并选择同一份保险箱时，会提示
「正在被另一个窗口使用」并退出。两个窗口各自读到旧数据、又各自写回，后保存的
会静默覆盖先保存的——原子替换只能保证文件不损坏，挡不住这种丢数据。
锁由 `data/` 下的 `*.lock` 文件实现，正常退出会自动删除；即使程序崩溃，
下次启动也能凭 PID 识别出陈旧锁并接管，不会把你永久挡在门外。

## 测试

```bash
python -m unittest discover -s tests -p "test_*.py"   # 核心 + 界面流程，共 146 项
python tests/live_check.py                            # 真实图形平台下的启动与配色自检
python tests/smoke_ui.py                              # 无头渲染全部窗口并截图到 tests/shots
```

界面测试运行在 Qt 的 `offscreen` 平台上，不需要真实显示器。

`live_check.py` 除了启动窗口，还会**采样三个面板的实际背景色**，浅色与深色各验一遍。
样式表覆盖不到的部件（典型是滚动区域的 viewport）会退回到系统调色板，在真实配色下
露出一块与周围不同的底色——这类问题只有采样像素才看得出来。

其中还包含一项**源码卫生检查**：用 AST 扫描 `psvault/`，找出"`return` 之后还有语句"的代码块。
这类问题不会报错、也不会执行，静默失效——项目里曾经因此丢掉过设置窗口的整组按钮，
所以把它固化成了测试。

**剪贴板保护的验证**（Windows 剪贴板是系统级行为，值得偶尔实测一次）：

```bash
# 终端 A：复制一段敏感内容并保持进程运行
python tools/clipboard_probe.py
# 终端 B：从外部进程读取剪贴板格式
powershell.exe -NoProfile -File tools/read_clipboard.ps1
```

敏感复制应能看到 `CanIncludeInClipboardHistory, CanUploadToCloudClipboard` 两个格式；
加上 `--plain` 参数作对照时则没有。确认无误后，按 `Win+V` 打开剪贴板历史，
里面不应出现刚才那段内容。

## 打包成 exe（单目录形式）

```bash
pip install pyinstaller
python tools/build_exe.py
```

产物在 `dist/密码保险箱/`：

```
密码保险箱/
├── 密码保险箱.exe        主程序（约 2.3 MB，图标与版本信息已嵌入）
├── _internal/            运行库，必须与 exe 一起分发
├── 使用说明.txt
└── data/                 首次运行后生成，存放保险箱文件
```

打包要点：

- **图标**：`assets/app.ico`，由 `tools/make_icon.py` 生成——圆角蓝色底 + 白色盾牌钥匙孔，
  与界面里的标志同源，内含 16/24/32/48/64/128/256 七个尺寸（小尺寸会加粗描边，避免糊成一团）。
  执行 `python tools/make_icon.py --preview` 可以输出各尺寸放大对照图。
- **版本信息**：`tools/version_info.txt`，显示在 exe 的「属性 → 详细信息」里。
- **数据位置**：打包后 `application_root()` 返回 exe 所在目录，数据保存在 exe 同级的 `data/`，
  不会写进只读的安装目录，也方便用户自己备份。

**排查“双击没反应”**：在命令行执行 `密码保险箱.exe --selftest`，
它会把运行环境自检结果（依赖、数据目录可写性、加解密、图标渲染、界面构建）写到同目录的
`selftest.log`，用退出码表示成功与否。源码运行时同样可用：`python main.py --selftest`。
